# 四个辅助头语义说明

本文档说明当前训练主线中的四个非 policy 头：

- `attack`
- `danger`
- `tactical`
- `value`

它们的目标不是替代传统引擎的单一静态评估，而是为**复盘解释**与后续**搜索调度**提供可解释的局面语义。临时讨论以 `temp.md` 为主；本文件用于长期保留这些头的正式定义与理解方式。

相关实现：

- Rust 标签生成：[crates/xiangqi_dataset/src/aux_labels.rs](/C:/projects/77xiangqi_engine/crates/xiangqi_dataset/src/aux_labels.rs)
- Python value 目标：[nn/src/nn/dataset_xrsh.py](/C:/projects/77xiangqi_engine/nn/src/nn/dataset_xrsh.py)
- 训练脚本：[nn/scripts/train/train_policy.py](/C:/projects/77xiangqi_engine/nn/scripts/train/train_policy.py)

## 总体原则

- 这四个头都不是“最终真理头”。
- `attack / danger / tactical` 是**复盘语义头**，用于描述人类能理解的局面状态。
- `value` 也不是传统引擎式“静态分数真值”，而是**结果导向的趋势监督**。
- 它们的职责是补充 `policy`，不是和 `policy` 争夺主任务地位。

一句话理解：

- `policy` 回答“人类大概率会走什么”
- `attack` 回答“我是不是在主动施压”
- `danger` 回答“我是不是很危险”
- `tactical` 回答“这个局面是不是开始要算了”
- `value` 回答“从整局结果看，这个局面对当前行棋方最终偏好还是偏坏”

## 1. `attack`

`attack` 表示**当前行棋方的主动施压程度**，不是胜率，也不是物质优势。

当前由三部分构成：

- 对敌方将帅的直接威胁
- 过河兵比例
- 子力深入对方半场的程度

这使它更接近：

- 攻势感
- 压迫感
- 主动推进意图

而不是：

- 我方是否已经赢了
- 当前局面数值上是否更优

因此：

- `attack` 高，不代表 `value` 一定高
- 物质落后时，只要持续对敌王施压，`attack` 仍可偏高

复盘里的典型解释是：

- “这一段你在主动压上去”
- “局面重心已经转向进攻”

搜索上的潜在用途是：

- 哪些候选着更值得优先展开
- 哪些分支允许更积极的扩展或更高宽度

## 2. `danger`

`danger` 表示**当前行棋方所处局面的危险程度 / 难受程度**，不是单纯胜率。

当前由四部分构成：

- 是否被将军
- 机动性是否偏低
- 物质压力
- 将帅暴露程度

它更接近：

- 我现在是不是很难走
- 局面是不是在变坏
- 有没有明显出事风险

而不是：

- 单纯“对方在进攻”
- 单纯“我少子了多少”

`danger` 和 `attack` 不是镜像关系。

常见情况包括：

- `attack` 高、`danger` 也高：双方互攻、局面尖锐
- `attack` 低、`danger` 高：我方被压制、防守困难
- `attack` 高、`danger` 低：我方相对从容地主动施压

复盘里的典型解释是：

- “这时你已经比较危险了”
- “不是简单落后，而是局面开始难受”

搜索上的潜在用途是：

- 危险局面的 extension
- 对防守应手增加关注
- 结合战术头判断是否需要更保守或更深地验证

## 3. `tactical`

`tactical` 表示**当前局面的战术/强制色彩强不强**，不是“这一手是不是战术好手”。

当前由三部分构成：

- 合法着里吃子着占比
- 合法着里将军着占比
- 当前是否已经被将军

它更像在回答：

- 这个局面是不是开始变尖
- 这里是不是要算而不是纯位置判断
- 可选着里是否有较多强制手段

它不等于 `attack`：

- 有些局面 `tactical` 高，但只是被迫应对，不是主动进攻
- 有些局面 `attack` 高，但一时没有很多强制手，`tactical` 未必高

复盘里的典型解释是：

- “这里已经进入战术阶段”
- “这不是一般位置手，要算变化”

搜索上的潜在用途最直接：

- 选择性扩展
- 静止搜索调度
- 根或叶节点上的战术优先级

## 4. `value`

`value` 是四个头里最容易被误解的一个。

它当前不是：

- `2 * attack - 1`
- 传统引擎式静态评估分
- 以皮卡鱼/NNUE 终评为唯一 teacher 的回归头

当前定义是：

- 先取整局结果
- 再乘一个随进程增长的 `progress^gamma`
- 最终转成**当前行棋方视角**的目标值

实现见 [nn/src/nn/dataset_xrsh.py](/C:/projects/77xiangqi_engine/nn/src/nn/dataset_xrsh.py) 中的 `value_target_side_to_move()`。

这意味着：

- 越靠前的局面，监督越接近 `0`
- 越靠后的局面，监督越接近最终结果 `-1 / 0 / 1`
- 它表达的是“结果趋势随对局推进变得越来越清晰”

所以它更接近：

- 人类复盘里的“这盘后来朝哪边走了”
- 结果导向的局面趋势

而不是：

- 引擎意义上的局面绝对真值

这样定义的原因是：

- 不强迫模型在开局就给出过硬的输赢判断
- 保留“复盘辅助”的产品语义
- 避免把整个项目悄悄扭成传统静态评估替代品

## 四个头之间的关系

这四个头不是重复命名的同一指标，而是从不同角度描述局面。

可以把它们理解成四个不同问题：

- `attack`：我是否在主动给对方压力
- `danger`：我自己是否处于危险之中
- `tactical`：这个局面是否带有强烈战术/强制色彩
- `value`：从对局结果回看，这个局面对当前行棋方最终偏好还是偏坏

一个局面完全可能同时具备：

- `attack` 高
- `danger` 高
- `tactical` 高
- `value` 暂时不明显

这种情况在实战中很常见，尤其是对杀、互攻、乱战局面。

这也是为什么本项目不想把一切压成“单一静态分值”：真实的人类复盘语义本来就是多维的。

## 为什么这四个头会比 `policy` 难学

当前训练现象里，`policy` 学得明显更稳，这并不意外。

原因主要有四类：

- `policy` 是强监督：每个样本都有一个明确的人类目标着
- `attack / tactical` 本身是稀薄语义，很多局面天然接近低值
- `danger` 虽然更连续，但分布偏窄，容易被模型学成中间常数
- `value` 的早局样本大量接近 `0`，很容易被“输出接近 0”这种保守解吞掉

因此四个头的困难点不完全是“loss 权重太小”，而是：

- 标签分布偏斜
- 语义本身低频
- 目标尺度不平衡
- 头之间对 trunk 的争夺不如 `policy` 直接

## 训练时应该如何看它们

不应只看一个总的 `val_aux_*` 聚合数。

更合理的观察方式是：

- 分别看 `attack / danger / tactical` 单头指标
- 对比常数基线，而不是只比较前后数值
- 对 `value` 看是否稳定优于零预测基线
- 同时看这些头是否伤害 `policy`

当前更合理的问题不是：

- “为什么它们没有像 policy 一样立刻学好”

而是：

- “这些头的定义是否足够有区分度”
- “损失设计是否让稀薄语义真正产生梯度”
- “它们学到的东西能否对复盘解释和搜索收益产生价值”

## 对长期路线的意义

这四个头存在的意义不是装饰，也不是为了“多头而多头”。

它们服务于两条长期方向：

- 复盘系统：把“为什么这个局面危险、为什么这一段在互攻、为什么这里要算”表达清楚
- 搜索引擎：把这些语义逐步转成 ordering、width、extension、leaf 调度等收益

因此判断这些头是否成功，不能只看单次训练 loss，还要看：

- 复盘解释是否更像人会说的话
- 搜索里是否真的带来更好的选择性验证

## 当前应保持的边界

- 不把这四个头直接退化成“伪装过的单一静态评估”
- 不默认把外部强引擎终评当作唯一真值来源
- 不在现有四头尚未完成收益归因前继续扩更多抽象标签

现阶段更重要的是把这四个头做实，而不是继续增加新 head。
