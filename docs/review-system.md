# 复盘系统（正式说明）

本文档定义本仓库当前的**短期主产品**：复盘系统。

---

## 1. 最小可用目标

当前最小可用复盘系统不是 `policy only`。

当前 MVP 目标是：

- `policy`
- `value`
- `danger`
- `attack`

它们分别回答：

- `policy`：人类更可能会走什么
- `value`：这步后局势趋势是变好还是变坏
- `danger`：当前局面有多危险
- `attack`：当前是否在主动施压

`tactical` 保留语义价值，但暂不属于最小复盘系统阻塞项。

---

## 2. 模型不是唯一信息源

复盘系统允许并鼓励结合三类信息源：

### 2.1 模型头

负责输出：

- 候选着
- 趋势
- 风险
- 攻势

### 2.2 真理引擎

负责输出：

- 客观优劣
- 明显战术对错
- 关键变化

### 2.3 滑动窗口前后文

负责输出：

- 前后几手的趋势变化
- 危险是如何积累出来的
- 攻势是如何形成或消退的

因此复盘系统不应只看单个局面，而应允许看一个局部时间窗口。

---

## 3. 推荐输出结构

一条完整复盘结论应尽量包含：

1. 推荐着与 Top-k 候选
2. 局势趋势
3. 风险等级
4. 攻势等级
5. 真理引擎校验
6. 前后文窗口解释

---

## 4. 推荐训练路线

1. 先做大一轮 `policy + trunk`
2. 等 trunk 接近平台
3. 冻结 trunk，单独训练 `value`
4. 冻结 trunk，单独训练 `danger`
5. 冻结 trunk，单独训练 `attack`
6. `tactical` 作为第二波增强头后补

---

## 5. 当前结论

当前最重要的不是“继续把更多头同时训进去”，而是：

- 先做强 `policy + trunk`
- 尽快做出 `policy + value + danger + attack` 的最小复盘闭环
- 再用真理引擎和滑动窗口把解释做完整
