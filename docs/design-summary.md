# 设计摘要（归档）

本文档收纳与助手讨论后**已定稿**的路线说明；**契约与格式**仍以 **`ARCHITECTURE.md`**、数据管线 README 及代码为准。

---

## 1. 定位：人类认知驱动的搜索（Human-Guided Search）

- **不是**造「单一巨型网络替代引擎静态评估」或完整复制皮卡鱼 NNUE 真理。
- **是**：轻量网络学 **人类棋谱与局面语义**（policy、危险、先手权等），提供 **候选空间与剪枝先验**；**Alpha-Beta + TT + 选择性扩展**承担战术深度、物质评估与验证。
- **分工**：**人味 / 大局观** → 网络；**机器侧穷尽与裁决** → 搜索与 `xiangqi_core`。

---

## 2. 能力边界（定性）

- **仅人类特级大师棋谱**训练时，策略先验大致落在 **人类对局分布** 内；对「人类谱中极少出现的最优冷门变化」，监督可能稀疏——这是 **分布覆盖** 问题，深层仍可由搜索补救，但整体上限受训练分布约束。
- **大规模自对弈 + NNUE**（如皮卡鱼）可把先验推到 **人类谱之外**，在同一引擎评测标尺下通常与「纯模仿人类」路线形成 **定性差异**。
- **可选折中**：在保留风格约束下引入 **受限自对弈** 或 **混合训练**（如在 policy/语义门控下于人类候选邻域探索），用于补盲点；与无约束自对弈导致棋风机器化是不同产品档位。

---

## 3. 关于 Elo 与数值讨论

- 讨论中出现的 **具体 Elo 区间**（如若干引擎榜单上的量级）仅为 **相对标尺下的示意**，随 **对手池、时限、引擎版本** 变化。
- **象棋与围棋 Elo 不可横向比较**。
- **本仓库不以某一估算 Elo 作为里程碑验收 KPI**；强度以实测与对局协议为准。

---

## 4. 价值（Value）与 Teacher

- **主线**：value / 语义头服务于 **人类局面感与剪枝**，而非默认把皮卡鱼 **Final/NNUE** 当作唯一回归真理。
- 以外部引擎作 Teacher 时，宜在文档与实验中 **显式标注用途**（对照 / 校准），避免 silent 扭转产品哲学。
